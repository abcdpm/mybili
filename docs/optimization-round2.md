# 第二次大优化 · 专题方案（第 12、23 项）

## 一、评论下载调度优化方案（第 12 项）

### 病根分析（已实测确认）
| 环节 | 旧版行为 | 后果 |
|---|---|---|
| 投递 | 每天 3:00 **一次性**投递当日全部任务（约 730 个） | 瞬时堆积 |
| 执行 | 每任务 `sleep(3-5)` + 分页抓取 `usleep`，单任务 1-5 分钟 | worker 被 sleep 空占 |
| 并发 | comments 队列仅 **2 个 worker**，日吞吐约 500-900 个 | **入 > 出，逐日累积** |
| 选取 | `--percent=3` 按总数百分比取最久未更新的 | 数据增长后配额不自适应 |

### 已实施（本次提交）
1. **错峰投递**：`--interval` 控制相邻任务投递间隔（默认当日任务均匀摊到约 20 小时），
   等待成本从 worker 转移到延迟队列；
2. **任务内 sleep 归零**：不再阻塞 worker；
3. **评论数聚合预取**：N 次 count → 1 次；
4. 定时参数 `--sleep=0`，附中文调度说明。

### 容量模型（配置建议）
```
日吞吐 ≈ worker数(2) × 86400 / 单任务均时(180s) ≈ 960 个/天
日配额 = 有效视频总数 ÷ 轮换周期天数   （如 24000 ÷ 30 = 800/天 ✔️ 在吞吐内）
```
**配额永远不要超过日吞吐**，否则换任何调度都会堆积。

### 后续配套（并入第 15 项「评论下载设置页」实施）
| 配置项 | 建议默认 | 说明 |
|---|---|---|
| 轮换周期（天） | 30 | 每 30 天全量刷新一遍评论（满足"不同时期评论不同"诉求） |
| 每日上限 | 自动 = 总数/周期 | 可手动压低；上限保护 |
| 投递间隔 | 自动摊 20h | `--interval` 显式覆盖 |
| 条数策略 | 自适应 | 固定条数 / 自适应（现有 log 模型）/ 增量追加 |
| 增量更新条数 | 20 | 在现有基础上追加 N 条（衰减模型） |
- 观测：`app:download-all-comments --status` 增加"轮换周期实际天数/积压量/最近完成时间"；
- 断点续跑：`comments_updated_at` 已是游标，天然支持中断后继续（选最久未更新优先）。

## 二、内存占用优化方案（第 23 项）

### 内存大头排查（按峰值影响排序）
| # | 位置 | 峰值估算 | 方案 | 状态 |
|---|---|---|---|---|
| 1 | `getVideosCache()`：Redis 大 JSON 字符串 → `json_decode` 全量数组 | **50-100MB/次调用** | 改「分块存储」：Redis List（每条一元素）+ `LRANGE` 按需取块，永不全量解码 | 待实施（收益最大） |
| 2 | `queueStats` lrange 10 万任务 | 数十 MB | LLEN + 抽样 500 | ✅ 本次已修 |
| 3 | `/api/progress` 全量响应 | 数 MB 序列化 + 双份数组 | 分块拉取 | ✅ 本次已修 |
| 4 | 图片优化（GD 加载原图） | 单张大图 50-200MB | `imagecreatefrom*` 后立即处理释放；限制最大边长；可选 imagick 流式 | 待实施 |
| 5 | 弹幕迁移/合并（单 cid 全量数组） | 数 MB/任务 | 已按 cid 分文件，天然有界 | ✅ 天然安全 |
| 6 | Horizon worker 进程数 × PHP 基础内存 | 2-10 worker × 40-80MB | supervisor `memory=128` 已限；`maxJobs` 定期回收 worker | 建议配置 |
| 7 | Octane 常驻 worker（web） | 每 worker 80-150MB | `octane.php` 限制 worker 数与 max-requests（定期重启释放碎片） | 建议配置 |

### 实施优先级
1. **P0（下一批）**：`updateVideosCache` 改 Redis List 分块存储（兼容旧 key 平滑切换：
   读取时新旧双读，迁移命令转换）；24K 视频的进度页/列表缓存从"全量解码"变为"按块读取"。
2. **P1**：图片处理流水线限幅 + 即时释放；
3. **P2**：Octane/Horizon worker 内存参数基线化（配置文件注释说明）。

### 验证手段
- 内存峰值回归：`memory_get_peak_usage` 埋点对比（测试中为关键路径加断言）；
- 生产观测：`app:calculate-system-stats` 增加 PHP 峰值内存上报；
- 压测：模拟 24K 视频缓存重建 + 并发 /api/progress，观察 worker RSS。
